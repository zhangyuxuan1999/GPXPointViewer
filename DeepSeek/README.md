# DeepSeek · 对话发现与问题登记

这里保存用户与代理（Codex / DeepSeek Harness 等）对话过程中产生的**观察、问题、改进建议和结论**。
目的不是替代正式设计文档，而是把"聊出来的东西"变成可追踪、可复核、可交接的持久记录。

## 文件约定

| 文件 | 作用 |
|---|---|
| `README.md` | 本文件：用途、约定、索引 |
| `issues.md` | **总登记表**。每条发现一个编号 `N-xx`，含状态、严重度、证据、建议 |
| `YYYY-MM-DD-<主题>.md` | 单次会话记录：范围、方法、实际执行的命令与结果、未做的事 |

命名用 ASCII，避免跨工具/跨平台麻烦；内容用中文，与项目其他文档一致。

## 怎么写

1. 会话结束时，在 `YYYY-MM-DD-<主题>.md` 记录过程与原始证据（命令、输出摘要、文件:行）。
2. 把**结论**登记到 `issues.md`，分配下一个编号；过程留在会话文件里，登记表不复制长篇。
3. 同一问题的新证据不回改旧结论，**追加**一条"更新"并改状态；旧记录保留。
4. 修复后把状态改为 `fixed` 并附证据路径；被后续工作解决的标 `obsolete`，不删除。

## 状态词

| 状态 | 含义 |
|---|---|
| `open` | 已确认，待处理 |
| `review` | 来自文档/静态阅读或旧结论，**尚未实测**，需定向复核才能定性 |
| `checked` | 已定向复核（读代码或跑探针），**未发现缺陷**，保留记录与残留风险 |
| `fixed` | 已修复，附源码或测试证据 |
| `obsolete` | 后续工作已解决，保留记录 |
| `wontfix` | 明确不做，写明理由 |

## 严重度

| 级别 | 判据 |
|---|---|
| P0 | 造成不可恢复损失，或结果/结论直接错误 |
| P1 | 正确性风险，或会让验收结论失真 |
| P2 | 工程质量、文档一致性、可维护性、可复现性 |

## 边界

- 这里写的是**观察与建议**，不等于已复现缺陷；标 `review` 的尤其如此。
- 产品事实以源码、构建和实际测试证据为准；本目录不修改、也不替代 `Tests/reports/` 与 `Tools/agents/records/` 的正式证据链。
- 不记录凭据、个人信息原文；涉及真实轨迹时只写文件名与统计口径。
