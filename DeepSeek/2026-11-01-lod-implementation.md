# 屏幕空间分层 LOD 实现记录（2026-11-01）

目标：北京预览分支上实现屏幕空间 LOD，接入实时回放与视频导出。
版本：每个可验收构建打 `beijing-rN` tag。

## 已定结论

- 采样单元：**2×2 屏幕像素格**（在目标相机下）。
- 每格预算：**K=2**；占用格不足 2 点全留。
- 稀疏轨迹兜底：每个占用格至少 1 点（等价屏幕间距 ≤2px）。
- 层数：5 层，覆盖 span 约 100km → 1km。
- 预计算时机：点“时光机”后、开播前；可接受 1–2 秒。
- 点通道现状：`spatialOrder`（Morton）预置换的 sx/sy/scolor + 全局 `lodStride`；
  LOD 需按层预生成置换缓冲，切层换缓冲 + draw 数，shader 不改。

## 关键实现约束

- 点通道现有 `resolvePointIndex`：非空间路径按时间序 `di=iid*stride`，空间路径用
  `order[di]` + 莫顿区段。LOD 需要第三路径：
  `di = iid`、`pi = lodOrder[di]`，位置/颜色直接用未置换的 `x/y/color` 读 `pi`。
- 这样不用重建置换缓冲，只需新增 `lodOrder` 缓冲 + uniform 开关；
  reveal 的区域/时间缓冲仍按 `pi` 索引，不受影响。
- LOD 激活时关闭空间剔除（LOD order 已经保证覆盖）；时间筛选走 shader 逐点判断。

## r9b/r9c 完成：接入渲染器（复用既有 useOrder==3 路径）

发现渲染器已有"任意原始下标列表 + 未置换缓冲"的 ordered 路径：
- `u.useOrder=3`：`pi = aux[iid]`、`di = pi`，位置/颜色按原始下标读；
- 因此 LOD **不需要改 shader、不需要重建置换缓冲**。

实现：
- `MetalPointRenderer.setLODLevels/clearLODLevels`：每层预建 order 缓冲；
- `render` 内按相机 `camera.w` 自动选层（选不粗于相机的最后一层）；
- `PointMapView` / `VideoExport`：单城回放按城市 bbox 建 5 层（2×2px、K=2），
  `setData` 时清除旧层。
- 非回放路径不启用 LOD；多城暂未启用。

构建：Release BUILD SUCCEEDED。tag `beijing-r9`。
待验证：实时画面与导出视频的稀疏段观感、HUD 实际绘制点数。

## r10 轨迹间距兜底

| 层 | 点数 | 平均间距 | >3px 对数 |
|---|---|---|---|
| L0 | 19,420 | 2.34px | 3,440 |

| L3 | 17,815 | 3.22px | 2,694 |

## r11 修正：层必须是“全区域 + 逐层加密”，不是“中心裁小”

发现并修正：首版每层把覆盖区域缩小到 span（中心裁剪），六环/海淀不在中心，
LOD 覆盖只有 28.5% / 3.7%。改为固定覆盖整个 baseSpan，层越细格越小。

真实数据离屏（512×512，点 1px）复测：

| 相机 | 全量点亮像素 | 10% 丢失 | LOD 覆盖 |
|---|---|---|---|
| 北京全景 | 1,354 | 14.2% | 99.9% |
| 六环西北 | 15,690 | 36.8% | 99.9% |
| 海淀 | 20,576 | 59.9% | 99.9% |

选层规则同步改为：选 `span <= 相机 span` 的最细层（宁可细一点，不丢覆盖）。

## r16 根据用户截图修复

1. **放大后轨迹消失**：`lodIndex` 在相机比最细层还细时回退到了 `0`（最粗层），
   点被抽到很少；改为回退最细层。
2. **轨迹发白**：新点发光窗口 2.5s/0.85 白色过强；改为 1.2s/0.45。
3. **2024-03-10 卡很久**：瓦片门控上限 2.5s；改为 0.8s，避免等底图把播放头冻住。
4. **六环没画**：单城计划没有过渡/片尾，城际（长途）区域永远不揭示；单城改为把
   城际点并入城市区域，并把城市时间范围扩到覆盖城际时间。

## r17 2024-03-10 卡顿定位

数据检查：2024-03-10 共 6,467 点，集中在 08–11 时和 19–23 时，
中间 **约 8 小时无任何点**（最大间隔 478 分钟）。
原按“本地日”切段，这一天内部的 8 小时空白按线性时间走，所以日期停在 3/10 很久。

修正：切段改为“活动间隔”（>30 分钟无点即断），空白段权重 0 被跳过；
同一天的两段活动分别按新覆盖格子分时间。

## r18 卡顿的两个根本机制

“卡住”有两个独立来源，不能只按某一天打补丁：

1. **播放头被瓦片门控暂停**：`displayTick` 里若底图瓦片在加载且相机静止，
   播放头最多等 0.8s（原 2.5s）。现在**完全移除门控**：播放头每帧必须前进，
   瓦片晚到只造成底图短暂空白，不能冻住时间轴。
2. **游标时间曲线平台**：显示日期来自 `cityTimeAt`；零时长/零权重段会让
   连续采样映射到同一时间，日期停住。现在切段按 >30min 活动间隔，且对
   `cityTimeAt` 强制严格递增（每步至少 5% 平均步长），日期不会长时间不动。

## r18 卡顿审计（真实北京数据，45s/60fps）

复现当前曲线（30min 活动间隔 + 新格权重 + 1024 采样 + 严格递增）后逐帧统计：

- **最长“没有任何新点出现”的墙钟时间：0.38s**
- **最长日期停留在同一天：4.35s**（这是 2024-03-10 六环那天；点仍在增加，日期停在同一天是正常的）
- **单帧最大日期跳变：约 97 天**（跳过空白活动间隔，属于预期）
- 曲线严格单调：true

结论：画面级冻结已消除；日期在数据密集的一天内可以停留几秒，但点一直在长。
播放头不再有任何门控，每帧必须前进。
