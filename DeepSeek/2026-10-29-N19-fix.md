## 根因回顾

`TrackData.recolor` 把 `time`/`ele` 原始列交给 `GeoCompute.normalized01`，缺失值是 `NaN`；
`vDSP_vclipD` **不会清掉 NaN**（本次实测：`[0, nan, 1, inf]` → `[0, nan, 1, 1]`），
随后 `Colormap.colorize` 里 `Int(tBase[i] * 255.0 + 0.5)` 对 `NaN` 做受检转换 → `SIGTRAP`。
`hasTime`/`hasEle` 是"任意点有值"，所以**部分缺失**不会降级到单色。

真实触发文件：`data/Garmin_Roma_Da1_GPVexported.gpx`（49,672 点，5 点缺 `<ele>`）。

### 2. `GeoCompute.swift` — 归一化输出保证有限

```diff
         vDSP_vdpsp(clipped, 1, &out, 1, vDSP_Length(n))
+        for i in 0..<n where !out[i].isFinite { out[i] = 0 }   // DeepSeek N-19：NaN/Inf → 最低档
         return out
```

两层都改是刻意的：`colorize` 是最终被 `Int(...)` 消费的地方（单点兜底即可防崩溃），
`normalized01` 保证"输出全部有限"这个契约，未来别的调用方也不会再踩同一个坑。

### 行为约定

- 缺失值（`NaN`）→ 色标**最低档**（与 `t = 0` 同一颜色）。
- `+∞` 仍按原来 `vDSP` 的行为夹到最高档（实测 `vDSP_vclipD` 对 `±inf` 正常夹紧，只漏 `NaN`）。
- 完整数据的行为、颜色、LUT 均未改变（回归里原有 101 项全过）。
