## 问题清单

### P1（任务数据/文档问题，不是 app 回归）：存档目录未带 `.fwdb` 后缀，`open` 被当作 GPX 解析

**现象**
按第 3 项原文打开 `$C/regions/2026_fog_new_db`，app 没有进入迷雾存档模式；`state.error` 报「文件里没有找到任何点（<trkpt>/<rtept>/<wpt>）。」，`modes` 一直不是 `["fog"]`，`totalCells` 只有 160,704（旧 Garmin 轨迹自身算出的格子），与期望的 1,209,290 不符。

**复现步骤（精确到命令和参数）**
```sh
C=$HOME/Library/Containers/de.wayne.GPXPointViewer/Data/tmp

# 1) 启动不带 GPXPV_REGIONS_BIN 的测试副本（简体中文）
pkill -f Tests/ui/app.noindex/GPXPointViewer.app; sleep 1.5
open -n --env GPXPV_UITEST_DIR=$C/uitest Tests/ui/app.noindex/GPXPointViewer.app --args -AppleLanguages '(zh-Hans)'

# 2) 按任务原文打开存档目录
python3 Tests/ui/ui.py "open $C/regions/2026_fog_new_db"

# 3) 查看状态
python3 Tests/ui/ui.py state regionstate

# 4) 强行切迷雾口径并看统计
python3 Tests/ui/ui.py "regionsmode fog" fogstats regionstate
```

**期望 vs 实际**

| 项目 | 期望 | 实际 |
|---|---|---|
| 启动后 `modes` | `["fog"]` | 120.48 s 内未变成 `["fog"]` |
| `fogstats.cells` / `totalCells` | 1,209,290 | 160,704（旧轨迹统计） |
| `fogstats.km2` | 48.152868 | 7.148733 |
| 错误 | 无 | `文件里没有找到任何点（<trkpt>/<rtept>/<wpt>）。` |

**根因**
- `GPXPointViewer/UITestHook.swift:98`：仅当 `url.pathExtension.lowercased() == "fwdb"` 时调用 `store.loadFwdb`；否则调用 `store.load` 走 GPX/CSV 解析。
- `GPXPointViewer/TrackStore.swift:896`：打开面板同样只把 `.fwdb` 后缀的目录当迷雾存档。
- 任务给的目录名 `2026_fog_new_db` 没有 `.fwdb` 后缀，因此不会触发存档导入；这与 `Tests/README.md:148` 的描述一致。

**证据 / 相关路径**
- `$C/uitest/log.txt`（钩子日志；失败后没有存档导入记录）。
- `$C/regions/r5_fwdb_nosuffix_error.png`（失败后主窗口为空状态；错误本身是独立的无标题 NSAlert，`windows` 显示为 `(无标题): x=590 y=382 w=260 h=139 id=_NS:87`，`shotview` 只截主窗口，截不到该弹窗）。
- `$C/regions/2026_fog_new_db.fwdb`（补验副本；同一数据加后缀后全部数字精确通过）。

**修复建议**
把测试数据目录改名为 `2026_fog_new_db.fwdb`（或让 `UITestHook` 对目录也走 `loadFwdb`）。这是测试数据/文档命名问题，不是 app 功能回归；改名后第 3 项全部数字与期望一致。
