# 测试任务文档（Tests/tasks/）与报告（Tests/reports/）

流程：Claude 做完一个功能 → 在这里写一份**只针对该功能**的任务文档（要测什么、怎么测、期望是什么、
哪些现有脚本相关）→ `Tests/run_deepseek.sh Tests/tasks/<task>.md` 交给 DeepSeek（只读 + 运行命令，不能改代码）→
报告落在 `Tests/reports/<时间>_<task>.md` → Claude 读报告、修改、再出下一轮任务文档，直到报告里没有问题。
每一轮的任务文档和报告都保留，不覆盖（报告文件名带时间戳；任务文档改版时另存 `<task>_r2.md`）。

任务文档模板见 `_template.md`。原则：只测这次改动真正会影响到的东西（全测要 40 分钟，不是每次都值得），
但该测的都要列全，不故意少测。

## 分工（2026-10-25 起）

特别重要的测试 Claude 亲自做，不外包；其余交 DeepSeek。每次都在给用户的汇报里写明哪些是自己做的、哪些外包了。
- **Claude 自己做**：确定性回归脚本（`Tests/ui/run_*.py` 里和本次改动直接相关的那几个）、核心数字一致性（迷雾统计面积公式、点归属与浮点参考逐点对照 `Tests/probes/regions/run.sh`、
  合成数据套件 `Tests/synth/runner/run_all.sh` 等引擎级探针）、把 DeepSeek 报告里的问题复现一次再修。
- **DeepSeek 做**：按任务文档机械执行、覆盖面广、步骤多的复测——多语言冒烟、反复开关/换数据/异常输入、截图与布局、崩溃日志、性能计时、环境差异（锁屏等）。

## 写任务文档的硬规则（2026-10-25）
- **每份任务文档必须自洽**：准备步骤、启动命令、钩子命令、锁屏说明、报告要求全部写全，**不许写「同前」「同第 N 轮」**让测试员去翻旧文档。直接从 `_template.md` 复制那两段再改。
- 期望值必须用当前构建现算（探针 `Tests/probes/regions/run.sh --real GPXPointViewer/Regions.bin --fwdb …` 等），不要从上一轮抄。
- 测单档数字要写明「新副本」。
