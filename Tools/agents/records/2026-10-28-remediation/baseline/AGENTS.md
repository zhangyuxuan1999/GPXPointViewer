- 主代理负责拆分、协调、核验关键结论和汇报；重要发现须核对源码或复现，不能仅复述子代理结论。

## 每次派发都必须保存记录

适用于子 agent、API、工作流以及失败/中断/未执行的尝试。

1. **调用前**在 `Tools/agents/AGENT_LOG.md` 追加计划。新建唯一目录 `Tools/agents/records/<日期或批次>/<任务名>/`，保存完整、自洽的 `task.md`、`meta.json` 和 `progress.md`。写清目的、输入、范围、允许修改的文件、禁止事项、预期产出、模型/强度、权限和恢复方式。
2. **派发时**保存实际参数、agent/session ID、开始时间。后续补充指令也保存原文；若工具不暴露实际模型回执、token 或费用，明确写 unknown/null，不用请求参数冒充服务端证明，也不把未知费用记成 0。
3. **执行中**维护 `progress.md` 的「已完成／正在做／下一步」和中间结果。可取得的正常输出、工具调用/结果、错误、退出码均存盘；不记录凭据，不要求内部思维链。
4. **结束时**保存完整 `output.md`、`result.json` 或等价结果、验证证据；更新状态和总日志。失败不能当通过，空结果不能当“没问题”。
5. **恢复时**先读旧任务、进度和结果，只继续未完成的工作。重试创建新目录并链接前次，不覆盖失败证据；未经验证不能把“已派发”标成“已完成”。
6. 写代码的代理还需保存允许修改文件的前后快照/哈希与新增/删除清单。仓库已有大量未跟踪文件，**单独 `git diff` 无法完整记录更改**。

历史 Claude 日志只读保留于：
`/Users/zyx/.claude/projects/-Users-zyx-Documents-GPXPointViewer/saved-agent-results/`。
其中 `AGENT_LOG.md`、`registry/`、`api-runs/` 可用于追溯。新的记录落在本项目，不需要改写旧账户目录。

旧 `Tools/agents/api_run.py` 和 `Tests/run_deepseek.sh` 不能直接当作满足本规则的留档器：前者存在并行累计与错误状态/差异记录问题，后者吞掉非零退出且仅保存最终文本。若使用，必须外层补齐记录与状态核验。旧费用累计、额度与到期日不代表实时余额。

## 项目开发与验证

- 先读 `README.md`、对应 `docs/*design.md`、`Tests/README.md`，再以当前源码和实际结果核对。旧文档的“未做”和数字可能已过时。
- 保留工作区已有改动；不要无授权 reset、清理未跟踪源码、重做历史任务或顺带执行 backlog。
- 核心数值、并发/取消、补点安全等关键回归由主代理或 Sol/Astra 核验；DeepSeek 适合边界清楚、步骤明确的复测。汇报时说明谁做了哪些验证。
- 测试任务书要自洽，版本另存 `_r2` 等；不能写“同前”。范围依据实际影响，不为通过改期望值；需要新副本或现算真值时写明。
- 公共 OSRM / Valhalla / Overpass **同一时间只允许一个测试客户端**；不并行联网测试，不同时开两个共用通信目录的测试副本。
- UI 测试优先使用已明确指定的构建路径 `GPXPV_APP`，避免误测旧版。测试副本与正式 app 共用偏好；测试后恢复。锁屏白图不能直接判成产品缺陷。
- 安装/覆盖 `/Applications` 前取得用户授权；仅研究或调用检查不等于授权安装、关闭正式 app 或运行全部 UI 测试。
- 本地化改 `Tests/l10n/translations/chunk_*.json` 后组装；不要把抽键输出覆盖到翻译目录。详见 `Tests/l10n/RULES.md`。
