# GPX 点位查看器（macOS 原生 App）

在 Apple 地图上**以点云方式查看 GPX 轨迹**的原生 macOS 应用（轨迹线/方向箭头是可选叠加），也支持一生足迹 CSV 与《世界迷雾》`.fwdb` 存档导入。
SwiftUI + MapKit + 自写 Metal 实例化渲染器，为 M4 的多核 CPU / NEON 向量单元 / GPU / 统一内存分别做了针对性设计，500 万点依然流畅。

## 环境要求

- macOS 14 (Sonoma) 及以上
- Xcode 16 或更新
- **不需要下载任何地图包**：底图默认来自 Apple 地图（也可切到 OpenStreetMap / OpenTopoMap / Esri 在线瓦片），联网按需流式加载，系统自动缓存

## 快速开始

1. 双击 `GPXPointViewer.xcodeproj`，等索引完成
2. 若提示签名：蓝色工程图标 → TARGETS → **Signing & Capabilities** → Team 选你的 Apple ID 个人团队（免费）
3. **⌘R** 运行；拖入 `data/` 里的 GPX 或按 ⌘O

> 构建配置说明：本工程的 **Debug 配置也开了 `-O` 优化**（⌘R 直接就是全速，代价是断点调试体验略差）。性能面板标题会显示当前是 Debug 还是 Release 构建。此前若见过"解析 24 秒"级别的数字，那是 `-Onone` 时代的 Debug 构建——手写字节解析器在无优化模式下会慢 10–50 倍。

## 打包成独立 App（双击即用，不开 Xcode）

方法一（推荐，最标准）：
1. Xcode 菜单 Product → **Archive**（会自动用 Release 构建）
2. 弹出的 Organizer 里选刚生成的归档 → **Distribute App** → **Custom** → **Copy App** → 选个保存位置
3. 得到的 `GPXPointViewer.app` 拖进「应用程序」文件夹即可，Launchpad/访达双击直接运行，图标就是工程里那个深色点曲线图标

方法二（快捷）：
1. 把 Scheme 切到 Release 后 **⌘B** 构建一次
2. 左侧文件树最底下 Products → 右键 `GPXPointViewer.app` → **Show in Finder** → 把它**拷贝**到「应用程序」

说明：这个 App 是用你自己的证书本地签名的，在你这台 Mac 上双击即开；拷给别人的话对方首次要右键 → 打开。以后每次改完代码，重新 Archive/构建一次就能得到新版 App。

## 使用说明

- **打开文件（支持多选合并）**：拖拽一个或多个 GPX 到窗口，或 ⌘O 多选；多文件**跨文件并行解析**（全部文件统一分块两趟直写，零合并拷贝），载入卡片显示**确定进度条**（已解析点数/总点数）；个别损坏/无点的文件**自动跳过并提示**，不会中断整批；
- **显示模式（单文件/重叠/对比）**：控制面板顶部切换。**单文件**＝新文件替换当前；**重叠**＝分批拖入的文件合并同图显示（一次拖入 ≥2 个自动进入），每个文件独立可选点色（8 色调色板自动分配），右侧**文件列表**支持逐个关闭、改色、**点击文件名在地图上高亮闪烁对应轨迹**（行底色跟随文件色）；恰好两个文件时可进入**对比模式**：左右分屏各显示一个文件，**位置/缩放/底图/点样式完全同步**（拖一边另一边跟随），顶栏可交换左右、调点大小/透明/底图透明度，关闭其一自动回单文件、再拖入新文件自动转重叠（重叠/对比下轨迹线与删除点停用；时间筛选/着色/导出等在重叠合并轨迹上照常）。合并数据名为 merge_N，载入时统一按时间重排；
- **设置面板（⌘, 或齿轮按钮）**：外观三向开关（白天/夜间/跟随系统，跨启动保存）、闲置展示开关与两档等待秒数、压力测试与重新加载；
- **Finder 空格预览 + 图标缩略图（Quick Look）**：App 内置两个 GPX 扩展——选中 .gpx 按空格出预览（轨迹折线 + 起点绿/终点红 + 点数/日期/时长概要；>32MB 大文件自动降级为轻量采样，扩展进程零大分配），**文件图标本身也显示迷你轨迹图**（始终走等距采样扫描，443MB 文件 0.35 秒出图，打开文件夹一眼识别路线）。自绘不依赖网络。缩略图扩展要求 App 位于 /Applications；首次使用前把 App 打开一次，图标若未刷新可注销重登或 `killall Finder`；
- **平面热力图**：控制面板"热力图"复选框——点云换成 GPU 实时密度热力（半分辨率高斯核累积 + 色标合成，随缩放/抽稀自适应归一化：单次经过蓝绿、反复经过的常走路线黄红）。多年数据一眼看出活动核心区；删除模式下自动回点显示；
- **迷雾模式（世界迷雾观感）**：控制面板"迷雾"复选框（从查看点/热力图切入迷雾时底图自动快速渐变到 100%，滑杆平滑随动）——未探索区域盖深色雾（浅色/深色外观各一套配色），走过的地方沿**轨迹线段**清出连续走廊（胶囊形清除区，半径 5–150 米滑杆可调（滑杆右侧格网按钮一键设为世界迷雾原始格宽 ≈9.55 米）、随纬度校正，参照《世界迷雾》约 9.5 米/格的世界网格；断点检测在 CPU 端按**原始相邻样本**预计算（间距 >100 米或时间差 >10 分钟即视为记录间隙，前缀和上传 GPU）——不同轨迹/暂停录制/丢星段绝不连线，只清端点）；清除区叠加**白亮冲刷 + 边缘柔光亮晕**（对比鲜明，与手机版世界迷雾一致），缩小后走过的轨迹钳制最小像素宽度保持可见。GPU 双 pass 逐帧实时（193 万点国家级视图 GPU ~6ms），迷雾自有按屏幕半径自适应的抽稀（与点云 LOD 解耦）；与热力图互斥，删除模式下自动回点显示；缩小进入地球视角时**迷雾风格延续到球面**（球面暗化 + 白亮轨迹，过渡不突兀）；迷雾行内可开"**迷雾统计**"卡片——等级/探索面积/地球占比/解锁格子/距下一级，算法与《世界迷雾》完全一致并用真实存档对账校准（2²²×2²² 世界格网、相邻样本沿线解锁、赤道格宽 2πa/2²²、纬度按 64 格 tile 行中心、等级=√(面积km²×250)、地球总面积 5.10072 亿 km²；与两份 .fwdb 存档护照真值分别只差 1.1ppb / 69ppb，等级与占比逐位一致），193 万点约 0.2 秒后台算完并按轨迹缓存；
- **.fwdb 迷雾存档直接导入**：把手机《世界迷雾》的 `.fwdb` 存档（目录，含 Sync 区块文件）直接拖进窗口（或 ⌘O 选取），自动切到迷雾模式，**以存档格子为数据源渲染迷雾**——文件名密码表解码区块号、zlib 解压、128×128 tile 表 + 64×64 位图逐位展开，与手机 App **一格不差**（放大到街道级能看到每个 ≈9.55 米小格的锯齿边界）；统计卡直读存档（80 万格 65ms 内载入完成，含面积/等级/占比，口径与护照逐位一致）。渲染为**多级聚合金字塔 + 视口实例化**：按屏幕像素密度自动选聚合级（块 ≈1 遮罩像素，带迟滞防级别抖动；近看回原始格），只收集视口±75% 边距内的块（每列二分查找、跨日界线自动环绕，<0.2ms），GPU 方格实例带 **1px 盒滤波羽边 + 亚像素饱和增益**直写迷雾遮罩（全程 <1ms/帧）——**远看轨迹融成 1–2 点宽的平滑细线（与手机版观感一致），近看仍是锐利的原始格**；聚合块按"线密度"归一化覆盖率，缩小后轨迹不消失；平移/缩放在缓存矩形内零重建；存档模式下点云/轨迹线等不适用控件自动隐藏或置灰，图片导出照常可用（按导出分辨率重选级别）。**可一次拖入多个 .fwdb**（或已在存档模式时继续拖入追加，同路径替换）：右上角出现存档列表，每档一个勾选框控制显隐、可单独关闭；渲染与统计取勾选存档的**格子并集**（重叠格只算一次），合并在后台完成不卡界面。迷雾行有"**平滑迷雾边缘**"开关（默认开）：开 = 每格渲染为径向高斯溅斑，相邻格的场相加后取等值线，阶梯格边融成圆滑连续的轮廓（手机版世界迷雾的扩散观感）；关 = 精确模式，0.5px 盒滤波抗锯齿，所见即存档原始小格。GPX 轨迹的迷雾模式（重叠多文件）下，右上角文件列表的色标自动换成**显隐勾选框**（迷雾同色，点色无意义；GPU 端按 fileID 位掩码逐段过滤消雾轨迹）。导入 GPX 或点 ⊗ 即退出存档模式；
- **时光机回放 + 视频导出**：控制面板时钟按钮启动——按真实时间流逝重放整段历史，轨迹/热力/迷雾从无到有逐渐点亮生长（GPX 与 .fwdb、单文件与多文件都支持）。回放规划一次性后台完成：事件抽稀 → 会话切分（时间断档 >6h 或无数据瞬移 >80km）→ 活跃区域聚簇（西安/北京/日本/欧洲级别，自适应合并到 ≤22 个）→ 驻留时长按活跃度分配、区域间 ~1.6s"拉高-俯冲"对数弧线飞行（跨度上限 5500km，绝不触发地球视角切换）；数据空档被压缩进飞行段，时间轴永远在走。底部时间轴：播放/暂停、当前日期、可拖动进度、总时长（30/45/60/120s）、**导出视频**、关闭；任何鼠标操作自动暂停接管相机。**视频导出**完全离屏渲染（与实时回放共用同一套规划，所见即所得）：按场景预取底图快照（驻留 + 飞行包络，并行 ≤4），逐帧独立 Metal 渲染器画揭示层 + 底图数字变焦（源切换 0.3s 交叉淡化）+ 时间轴丝带合成，AVAssetWriter H.264 .mp4（1080p/4K，30fps），24 秒 720p 实测 ~36s 导完。.fwdb 的时间线来自区块文件的同步时间（存档里唯一的真实时间信息；全部区块时间相同的导出档会提示不可用）；
- **3D 热力柱**：热力图行的"3D 热力柱"开关——把（时间筛选后的）轨迹点按世界迷雾格网聚合成方块（块面积 1/4/9/16/25/36 格可选），块内点数 → 对数归一的柱高与颜色（绿→黄→红），常去的地方"高楼耸立"。两种样式：**棱角**（独立平顶方柱）与**平滑**（顶面四角取邻块平均、连绵成地形）。自绘透视场景带轨道相机——拖拽旋转、滚轮/捏合缩放、右键拖拽平移，能绕到任何高柱四周查看；进入时自动落到最密集区域的城市尺度。地面铺当前底图截图（贴近时自动补一张脚下高清快照）。性能：CPU 分块视锥剔除 + 按投影尺寸分级绘制（远块只画顶面 6 顶点）+ 顶点级亚像素墙面剔除，190 万点 → 110 万块的极端场景 GPU 2–7ms，交互满帧；
- **高清图片导出**：控制面板"图片"按钮——把当前视图（平面地图或地球视角，含热力图/像素地球）离屏渲染为 **4K/8K PNG**：平面 = MKMapSnapshotter 底图 + 全量点云图层合成（可选纯点云透明背景、可选比例尺），地球 = 整幅自绘场景（可选透明太空）。导出完成自动在访达中显示；
- **导出联动时间筛选**：正在按年/月/日/自定义查看某段时间时点导出，导出面板自动预设为同一段（查哪段导哪段）；**导出时文件名自动为 `merge_N_GPVexported.gpx`**（N = 输入文件数）。标题显示**文件名**（悬停立即展开全名）、点数，以及**数据的最早/最晚日期**（精确到日）
- **时间筛选**：数据跨多日时控制面板出现"时间筛选"（全部/年/月/日/自定义，粒度自适应：单年/单月直接显示为文字，绝无单选项选择框）。筛选是**索引子区间**实现（数据时间有序时二分查找，零拷贝零重建）：渲染、悬停、圈选删除全部只作用于筛选内的点，性能面板"点数"行显示 筛选/全部
- **地球视角（无缝连续缩放）**：平面地图和自绘 3D 地球是**同一个连续缩放空间**——不停缩小，当可见地面宽度达到约一个大洲（~6500 km，或任何底图缩到 MapKit 的封顶）时自动丝滑过渡到地球球体；在地球上放大，穿过衔接比例尺又自动滑回平面地图。接管点特意选在 MapKit 自己的球体渲染出现之前（标准图的封顶、卫星图的原生地球都在其后），所以点永远不会再"飘"出球外。**过渡瞬间两边的中心位置与比例尺严格相等**（由当前地图比例尺实时解出球距），配合淡入淡出没有跳变；载入横跨大洲/全球的数据时直接以地球总览打开。地球有**深/浅两套地表外观，自动跟随系统日间/夜间模式**。「底图」透明度滑块在球面上同样生效（压暗地表，点云不受影响，与平面语义一致）。太空布景：**1100 颗随机装饰星**（实心星核 + 柔和光晕，随地球一起转）、**真实位置/真实月相/真实月面纹理的月球**（Schlyter 历表算 RA/Dec + GMST 得星下点；正面圆盘纹理按真实月海布局烘焙——雨海/静海/风暴洋/第谷辐射纹都在；球体冒充着色器用真实太阳方向打光，月相自动正确）以及**月球轨道细线**（轨道半径压缩到 2.2 球半径便于观赏，倾角/椭圆率/朝向保持真实；绕到球背面被深度测试自然隐没，贴近球面看轨迹时月球与轨道自动淡出）。**闲置展示模式**：地球视角 3 秒 / 平面地图 5 秒（默认值；两者都可在设置面板 1–60 秒调节或整体禁用，跨启动保存）无操作自动进入——文件导入、拖放悬停、打开/保存对话框、地图拖拽缩放、鼠标按下都算操作，不会刚导入完就进入展示；**任何操作退出展示时自动渐变回进入前的视角**（平面位置/缩放原样恢复，地球视角相机缓动回原朝向，被展示强改的地球风格也一并还原）——UI 面板先 0.3s 快速渐隐；平面出发时先用约 1.1s 把**地图色调渐变到展示地球的色调**（深色外观渐成暗夜蓝黑、浅色外观渐成浅灰，由外观自适应的调色纱罩逐帧驱动），色调到位后地图才开始逐渐缩小、无缝滑入像素地球（纱罩随切换淡出），地球继续拉远，直到**整条月球轨道恰好入画**，然后地球缓缓扶正（地轴竖直）、按真实方向自转、月球沿轨道公转（约 90 秒一圈）；任何鼠标动作立即恢复手动控制、面板渐现。流星**从画面外进入、斜穿整幅画面、连尾迹一起完全飞出**才消亡。地球视角右侧有悬浮控件可切换两种风格：**写实**（纹理球 + 原始点云）与**像素**——点阵大陆/海洋（内置陆地掩码采样，不分国界）、你的数据按 0.8° 网格聚合成**数据柱**（格内点数取十位数 → 对数高度 + 蓝少红多色温，190 万点单趟扫描毫秒级聚合，逐帧零 CPU）、随机**流星**划过背景，并可开关**地名**（默认关；只标有数据的省会/大城市，内置全球 130+ 城市库，CALayer 逐帧定位、背面自动隐没）；像素模式同样跟随系统日/夜外观。轨迹点带**海拔抬升**（夸张 ×50：万米巡航 ≈ 0.084 球半径），侧视时飞行轨迹从球面拱起、立体可辨——套索圈选与悬停拾取都按抬升后的位置命中。地球本体完全自绘（Metal）：UV 球网格 + 内置 Natural Earth 暗色地表纹理（视图空间光照 + 大气辉光），点用载入时预算好的球面单位向量单 draw call 实例化，**真正贴在球面上**，背面点由 GPU 深度测试自然遮住。手势约定：**拖拽只旋转，滚轮/捏合只缩放，绝不混动**。球面上**悬停详情、点击选中、手绘套索删除全部可用**（光线-球体求交 → vDSP 弦距最近邻拾取；套索是屏幕空间命中 + 地平线剔除，绝不误选球背面的点；删除模式下右键拖拽旋转地球）；时间筛选、LOD 连续抽稀（同一套中位段长模型）照常生效。轨迹线与比例尺在球面上自动停用，回平面即恢复
- **载入时按时间重排**：多轨迹备份文件常见时间乱序/缺失，载入时自动按时间稳定重排（缺时间的点排尾）——时间筛选因此总是可用，测速与方向箭头也回归正确时序
- **着色**：速度 = 慢绿→快红，时间 = 出发绿→终点红（均经黄过渡），海拔 = 低黄→高蓝（经绿青过渡）；**单色模式下会出现"点颜色"取色器，可以自选任意颜色**；色标按 2–98 百分位缩放；数据缺时间/海拔时自动降级
- **底图来源**：除 Apple 的标准 / 卫星 / 混合，还能切到 **OpenStreetMap**（画隧道虚线与分向车道——就是补点用的那条路，Apple 底图不画隧道）、**OpenTopoMap**（地形，最大 17 级）、**Esri 影像**；任何底图上都能再打开「叠加 OSM 隧道」（视野 ≤ 40 km 时按视野向 Overpass 取 tunnel=yes 的公路/铁路线，两色虚线）。外部瓦片只按视野取、本地缓存 ≤ 300 MB、不预取不批量下载，左下角显示署名可点开版权页（详见 `docs/map-sources.md`）。Google 地图不做：需要密钥计费，且条款禁止在 Google SDK 之外使用其瓦片
- **底图滑块**：把地图底图往暗处压（20%–100%），点云对比度立刻上来，卫星图上尤其有用
- **白描边**：开关（默认关）。点稀疏时开着好看，点密集时关掉才能看到真实的渐变色
- **轨迹线（方向箭头）**：打开"轨迹线"后出现线样式控件——**线颜色、线宽、线透明**，以及"方向箭头"开关。开着箭头时每条线段渲染为从时间早的点指向时间晚的点的箭头；缩放太远时亚像素线段会在 GPU 上自动剔除，不会糊成一团
- **悬停/点击**：悬停看详情，点击固定详情卡到右上角
- **自动降采样**：默认开。抽稀率随比例尺**连续**变化（性能面板"采样率"行显示 1/n 与上屏点数），放大自动回全量；悬停拾取按同一采样率跳步，与所见一致
- **导出**：控制面板「导出」。粒度自适应数据跨度：跨多年给 全部/年/月/日/自定义；同一年不再出现年选择（直接显示年份文字）；同一个月只需选日；**单日数据直接导出，不弹面板**。时间边界按本机时区，日期用明确的「年/月/日」下拉。导出文件名自动追加 `_GPVexported`（再次导出自动递增 `_2`、`_3`…），GPX 内嵌名同步
- **删除点（预删除事务 + 手绘套索）**：「删除点」进入预删除模式——按住左键**手绘任意形状圈选**（不要求闭合，松手自动把首尾连直线），圈内点被标灰暂存，**真实数据不动**；可连续圈多次，**⌘Z / 撤销按钮逐步回退每一次圈选**（像 Word 一样不限步数）；「执行删除…」弹窗确认后整批一次落地（最终操作），「取消/退出/Esc」什么都不删。右键拖拽平移地图。命中判定为包围盒预筛 + 射线法点在多边形内（多核并行，190 万点毫秒级）
- **断档补点（隧道）**：控制面板「补点」进入，右侧列出时间空洞类断档（Garmin 过时时钟、信号中断、采样稀疏三种成因）。单处：选一处后两端为锚点 A/B，「路网草稿」向公共 OpenStreetMap 路线服务取 A→B 的道路几何作折线，拖顶点/挪锚点后「应用」按弧长等距插点。**批量**：「一键补全部」三步走——① 先按「段」定公路还是铁路（轨迹按停车 ≥10 分钟切段，每段抽几个行驶中的点问 Overpass 150 m 内有没有铁路，贴铁路 ≥2/3 判铁路、远离 ≥2/3 判公路，拿不准退回整段速度，可整段手选；只补公路默认开）；② OSRM 与 Valhalla 两路并行取草稿（每个服务 1 秒 1 次），✓ 没疑点 / ⚠ 有疑点 / ✗ 失败 统计，「只看有疑点的」过滤后点行飞到主地图核对；③ 预览勾选后一次落地。**隧道口定位漂移**：以上下文路由的整条几何为「路」，锚点离路 >20 m 而外侧几个点回到路上，就把锚点往外挪到第一个在路上的点，被跳过的漂移点随区间替换；近上下文（150 m）路由不干净时自动改用 600–900 m 外的远上下文；裁剪按沿线顺序取方向一致的第一次经过（绕圈掉头不进草稿）；挪不动的残余偏移在末端 80–400 m 内渐进靠拢（锚点在匹配半径内就算在路上，补点留在路网几何上不往 GPS 噪声弯；隧道 way 节点稀疏时保留裁剪投影点、起止段不是路网几何会提醒）；Garmin 进隧道后按最后航向外推出来的几个假点会并入替换区间，出隧道后位置对、只是时间戳滞后的点保留位置、时间按出口速度回推（修改记录里记作「改时间」）；1 秒跳一百多米的短隧道也能检出；取回路径后再按**通行侧**（靠右/靠左，按国家查表）校验：真实点应贴着路线或在它的内侧车道，一致落在对向车道那一边就判为吸错车道并降级该候选。**隧道群合并**（默认开，候选面板可关）：相邻两处「信号中断」类断档之间只有 ≤3 个点、≤90 秒就并成一处一次补完（「采样稀疏」的连续步之间是真实点，不并）——一生足迹在隧道群之间常只记到一两个离路几百米的网络定位假点（全量备份 4493 处断档里 2986 处成群），并起来后，区间内贴着路网路径（手机数据 20–30 m 内）的真实点保留、飘了的替换（Garmin 的区间内点是出口处时间戳过时的点，一律替换）；Garmin 隧道群之间是几十个贴路的真实点，不会被并。可导出整条 GPX 或仅补点增量。**铁路也补，但只补隧道**：铁路断档取 OpenStreetMap 铁路路径（Overpass），路径上的铁路线段自带 tunnel 标签，裁出的 A–B 段里隧道占比 ≥50%、直线 ≤60 km、时长 ≤25 分钟才补；否则标「不补」（多半是车厢里收不到信号，DB/高铁可以几百公里没点，这种请从 gpx.studio 导入）。「只补公路」默认关。**网络不好会提示**：系统离线、或最近 3 分钟内请求连续失败/超时/很慢时，补点操作条、批量窗口、修改记录窗口顶部出现橙色横幅说明原因，离线时取草稿/地图判段按钮置灰。**精确模式（两路交叉验证，用时间换精度）**：批量第 1 步开始按钮旁的开关（预计用时随开关显示）。开了之后每处公路断档同时发给 OSRM 和 Valhalla 两个路线服务（都用 OpenStreetMap 数据、算法不同），取回后比对几何：走的是同一条路（相差不到 10 m，分歧段 ≤ 15–40 m）才自动采用（采用警告少、贴路近的那份，另一份留着可「改用另一条」）；不是同一条路的、或只有一路给出结果的，不勾选落地，地图上两路都画成蓝色（OSRM 实线、Valhalla 虚线），点行后用「选一条…」选一路 / 直线 / 都不补，第 3 步「只有一路结果的全部采用」可一键处理没比对的。某一路连续连不上会被停用，剩余只走另一路并标「没比对」。能查出：一路吸到匝道/辅路/对向车道、一路绕远；查不出：两个服务用同一份地图和同一组锚点，锚点本身漂到旁边路上时两边会一起错（这种会另加一条疑点）。铁路只有 Overpass 一个来源，不比对。耗时约为普通模式的两倍。单处补点的「路网草稿」菜单也有「沿公路取路径并交叉验证」，取回后操作条上有 OSRM / Valhalla 切换，来回看两份草稿。**补点点距**默认严格按这处断档两侧的原始点距（取整到 1 m，5–100 m；两侧点太少算不出就按整条轨迹的采样中位点距），拖滑块才改；勾上「显示补的点」能把要插进去的合成点画成橙点（折线照旧）。批量第 1 步的地图判段（问 Overpass）可以不等：已经知道公路还是铁路就直接定、点开始，或点「停止，按表里的判断」。**落地前审阅**：批量第 3 步「审阅落地效果…」在修改记录窗口里打开预览——总览整条轨迹上会补哪里，‹ ›（或 ← →）逐处看将新增的点（绿）和将被替换的点（红），逐处开关落不落地，看完在那里一键落地；落地后批量窗口自动关闭，主窗口顶部横幅「已落地 N 处 · 新增 X 点 · 替换 Y 点」。**路网证据留档**：每条落地记录带当时取到的路网草稿（精确模式两路都留）、依据、贴路距离、一致性、警告与全部说明，修改记录的详细页画出草稿折线并可弹出说明回查；直线补点的也留着取到的草稿。精确模式两路都在时，详细页有「OSRM | Valhalla」切换（采用的那份带 ✓）：显示的那份画成粗实线（绿 = 采用、蓝 = 未采用），另一份细虚线，依据行与「说明…」跟着切换，只是看、不改采用；两路坐标逐点相同时会标「两路几何完全相同」。**路网结果缓存**：同一个文件打开期间，每处断档向每个来源取过的结果（草稿或明确的「无路」）都留在内存里，按完整取路输入做键；取消落地、放弃批量、撤销/还原后再跑一遍不会重新请求（第 2 步进度与第 3 步统计显示「命中缓存 N 处」，草稿说明首行注明来自缓存），换文件时清空。要重新向路网取：批量第 2/3 步「重新获取全部…」（有确认）、右键某一行「重新获取这一处」（只重取那一处，其它不动），单处补点操作条「重新取（忽略缓存）」。**修改记录地图**有自己的底图（标准 / 卫星 / 混合）和「浅色」开关，点一律白描边——注意 Apple 标准底图不画隧道几何，补在隧道里的点看着像在路外，切到卫星/混合就能看到洞口。**2026-10-26 隧道补点修正**：路网几何的两端后处理不再把隧道 way 的首段直边裁掉、也不再按下一段的延长线把起始补点推到路外（第 14/16/19 处"跑到旁边的路上"的根因）；Garmin 进隧道后航向/步长锁死的外推假点（链长 3–6、冻结前在转弯）自动并入替换区间；出口处位置正确、只是时间滞后的过时点保留位置、按出口速度回推时间（修改记录里单列「改时间」）；1 s 跳 60–150 m 后 4 s 内时钟回正的微型隧道也成为候选
- **乱跳清理（回放点 + 乱跳段）**：手机和 Garmin Explore App 在车厢里收不到信号时并不留空洞，而是把存过的旧位置来回回放（RE1 Koblenz–Trier 9638 点里 5142 个坐标一字不差地重复，沿 3–4 km 的线来回扫；一生足迹全年 11.8 万点里 1.45 万个，全在坐火车的日子），或两路定位交替（一路实时、一路滞后几十秒）。专用记录仪（Garmin eTrex/Edge 类）没有这个问题。两层处理：① **回放点**——坐标与 10 秒到 30 分钟前某个点位级相同、期间轨迹已离开 ≥300 m、且是在移动中记下的点；补点操作条出现「清理回放点 N」，一键删掉（几何不变，每个位置首次出现的点留着），记成一条「回放点清理」修改记录可还原。② **乱跳段**——「找乱跳」（默认开）按整秒聚合后，相对最近 60 秒已接受轨迹的步长/速度/行进方向，逐步判「大跳」（d > max(300 m, 2.5×参照速度×步时 + 4×局部步长)）和「倒退」（相对行进方向后退 > max(200 m, 3×局部步长, 步时²)），直到后面连续 20 秒步步合理、弦速不超参照上限才结束；乱跳段当断档列进候选与批量（成因列显示「乱跳」，悬停看大跳/倒退步数），有路径就整段替换，两锚点太近或隐含速度不合理的在本地判「只删点」不发请求；铁路不像隧道、或被路网判定拒绝的乱跳段默认也落地「只删乱跳点」（网络连不上的失败不默认删；可逐行关），删点时保留沿 A→B 单调推进、车速合理的那一路（两路定位交替时真的那一路）；只删点的落地记为「删除」而不是「补点」。「只补公路」下铁路上的乱跳段不取路径、直接只删点。超过 30 万点的文件候选检测在后台进行，不再卡住界面。单秒瞬时速度不作判据：成批冲刷的时间戳让 1 Hz 噪声里单秒速度常达 200–700 km/h
- **修改记录（单文件模式）**：控制面板「修改记录 N」（补点操作条上也有）打开独立窗口，列出本次会话对这条轨迹的全部修改——补点落地的每一处断档、每一次圈选删除。**总览**：整条轨迹蓝色、新增的点绿色、删掉的点红色，右侧清单按轨迹顺序排列；**详细**：地图刚好框住某一处修改（四周留边、至少 160 米见方），显示「国家 - 州 - 城市」（Apple 地图逆地理编码）与轨迹时刻，‹ › 逐处人工校验；每一处可**一键还原**（按点的值找回、按时间插回，不依赖下标，所以逐处还原互不影响），「全部还原」需确认。还原后补点清单与候选列表同步更新；换文件时记录随旧轨迹作废
- **地区统计（国家 / 省州 / 中国地级市）**：控制面板「地区统计…」（查看点模式与迷雾模式可用，热力图模式隐藏）打开独立窗口，对标《世界迷雾》新版的行政区卡片——到访国家列表（国旗、名称、面积、到访下级行政区 n/N）→ 点进去看省/州排行 → 中国再下钻到地级市（直辖市到区），绿色角标 = 到访的下级行政区数。两种口径：**点** = 落在该地区的轨迹点数与到访天数（本机时区按日去重，另给首次/最近日期）；**迷雾** = 该地区内解锁格子的面积、等级与占比，算法与「迷雾统计」卡片同源（同一套解锁格键 + 逐格纬度面积，等级 = ⌊√(km²×250)⌋）；.fwdb 存档只有迷雾口径。每行给占上一级的比例，点一行主地图画出该地区边界（橙色描边 + 淡填充，洞作内环）并飞过去，列表上方出现该地区的卡片（面积、探索占比、等级 / 点数、到访天数、首次/最近）；行末 › 下钻，列表末尾的「其余」行 = 上一级减去各下级（没有更细划分的区域、下级边界之间的缝或洞）。点归属按最细一级落点再逐级汇总：边界数据预处理成 `GPXPointViewer/Regions.bin`（`Tools/build_regions.py`：geoBoundaries CGAZ ADM0 国界 + Natural Earth 10m 一级行政区 + 阿里云 DataV 中国地级边界，Douglas–Peucker 简化到 150 m，微度整数顶点，1°×1° 格候选索引），运行时按 0.01° 单元缓存（单元内没有任何边界经过才整单元同属，有边界的单元逐点判，飞地 / 窄条 / 小岛都不丢）+ 偶奇射线法整数判定，跨国格里子级命中还要国家多边形也包含；12 万点 / 37 万格在后台零点几秒算完并按数据源缓存。离线探针 `Tests/probes/regions/run.sh` 逐点对照浮点参考。内置数据：国界用 geoBoundaries CGAZ ADM0（CC BY 4.0，www.geoboundaries.org；按美国国务院国界线裁剪），省/州用 Natural Earth 10m（公共领域），中国地级与港澳分区用阿里云 DataV GeoAtlas（GCJ-02 已反解为 WGS-84）；法/意/西/英按大区分组（省作下一级），简体名统一（繁体字、台湾译名清洗）；5319 个地区 29 MB。数据许可：geoBoundaries CC BY 4.0（www.geoboundaries.org），Natural Earth 公共领域，DataV GeoAtlas 阿里云开放数据。与世界迷雾卡片对账：德国 34.286 ↔ 34.291 km²、中国 497.97 ↔ 498.15、北京 47.34 ↔ 47.32，地级/区级差 0.1–1.5%。迷雾存档目录不要求 `.fwdb` 后缀（按区块文件名识别）。格式说明见 `docs/regions-design.md`；
- **多语言（简体中文 / 繁體中文 / English / Deutsch）**：界面默认跟随系统语言；设置面板（⌘,）里「语言」一行可单独指定，改完点「立即重启」生效（也可在 系统设置 › 通用 › 语言与地区 › 应用程序 里设）。源语言是简体中文，字串表 `GPXPointViewer/Localizable.xcstrings`（Quick Look 扩展另有一份），键就是中文原文；翻译由 `xcodebuild -exportLocalizations` 抽键 → 按块翻译 → 脚本组装（占位符逐条校验）。专业词固定对照：补点 Gap Fill / Lücken füllen / 補點，断档 gap / Lücke / 斷檔，回放点 replay points，乱跳 jitter，落地 Apply / Übernehmen，修改记录 Change Log / Änderungsprotokoll
- **清除**：「打开 GPX」左侧的 ⊗ 按钮，一键清空当前导入的文件
- **比例尺**：底部居中，1-2-5 取整，随缩放实时更新
- **默认显示**：导入后默认单色红点；多段/多日轨迹自动禁用「轨迹线」（跨轨迹连线无意义且耗性能）
- **压力测试**：一键生成 100 万 / 500 万合成点，走与真实文件相同的完整流水线
- **性能面板**：各阶段耗时、GPU 反压等待、交互帧率、采样率，标题显示 Debug/Release 构建
- **多窗口**：⌘N 可开多个窗口同时看多个 GPX，互不影响

| 10 核 CPU（4P+6E） | **两趟式并行解析**：Pass1 各块并行数点（memchr 速度）→ 前缀和定偏移 → 成品数组按精确总数一次性免零填充分配 → Pass2 各线程**直写全局偏移**。零 append、零合并拷贝、零锁；"起始标签所有权"分区保证两趟一致；body 单趟前向扫描 | `GPXParser.swift` |
| NEON 128-bit SIMD | 墨卡托投影、haversine 测速、归一化全部走 Accelerate（vForce/vDSP）向量核函数，零标量循环 | `GeoCompute.swift` |
| NEON SIMD | 悬停拾取 = vDSP 向量化全量 argmin（dx²+dy²+minvi），百万点约 1–2 ms，无需空间索引 | `TrackData.swift` |
| 10 核 GPU | 全部点**一次实例化 draw call** 画完；着色器画抗锯齿圆（描边可选） | `MetalPointRenderer.swift` + `Shaders.metal` |
| 10 核 GPU | 方向箭头线：第 i 个实例直接读点位 SoA 缓冲的第 i、i+1 项，方向/法线/箭头张角全部在顶点着色器上并行算——**零额外几何内存、零 CPU 每帧工作**，箭杆+箭头共 2 次实例化提交 | `Shaders.metal`（segmentVertex） |
| 统一内存 | 顶点缓冲 `storageModeShared`：CPU 数组和 GPU 读同一块 DRAM，零拷贝零同步 | `MetalPointRenderer.swift` |
| — | RTC 精度方案：double 中心 + float 偏移，深度放大不抖动（误差 < 1 cm） | `TrackData.swift` |
| — | `presentsWithTransaction` 把 Metal 提交挂进 CA 事务，点云与底图逐帧锁定 | `MetalPointRenderer.swift` |
| — | 全程 SoA 内存布局：解析产物 → Accelerate → GPU 顶点属性同一批连续数组 | 全链路 |

数据流：`字节流 ─(多核无锁解析)→ SoA double ─(vForce 投影/测速)→ RTC float ─(LUT 着色)→ 共享内存 GPU 缓冲 ─(1 次 instanced draw)→ 屏幕`

## 常见问题

**Xcode 控制台一直刷日志，是 bug 吗？**
逐条对号：
- `NSHostingView is being laid out reentrantly` / `layoutSubtreeIfNeeded…` —— 曾是本 App 的问题，**已修复**：以前在布局回调里同步渲染 Metal 层并触发相机动画，会在 SwiftUI 布局期间再次进入布局；现在所有重绘/相机动画都合并调度到布局周期之外（每轮 runloop 至多渲染一次）
- `CAMetalLayer ignoring invalid setDrawableSize 0×0` —— 已加窗口守卫，本 App 不会再发；若还偶尔出现，那是 MapKit 自己的 Metal 层在窗口开关瞬间打的
- `Publishing changes from within view updates…` —— 已修复（设置绑定延迟发布）
- `We may not be tracking resources correctly…VectorKit` / `Resetting GeoGL/GeoCodec zone allocator` —— **关闭地图窗口（比如 ⌘N 开的多窗口）时 MapKit 自己的拆除日志**，无害，Apple 框架内部行为
- `Failed to locate resource named "default.csv"` / `Unable to obtain a task name port right` / `no reasons from unifiedReasons…ChatGPT` —— 系统/框架日志噪音，与本 App 无关
想清净：Edit Scheme… → Run → Arguments → Environment Variables 加 `OS_ACTIVITY_MODE = disable`。打包成独立 App 后没有控制台，眼不见为净。

**几百万点还会卡吗？（自动降采样 LOD）**
缩小看全图时，几百万个半透明点叠在少量像素上，GPU 填充率（overdraw × alpha blending）是硬瓶颈；GPU 排满后 `nextDrawable` 还会反压阻塞主线程（性能面板"等待"行），拖拽跟着卡。默认开启的**自动降采样**用"中位段长模型"决定抽稀比：唯一的判据是**典型相邻点在屏幕上的间距**（加载时 vDSP 采样估计相邻点距离的中位数，每帧乘以当前 px/merc 缩放），间距远小于 0.5px 说明大量重涂，`stride = ceil(0.5px ÷ 屏幕中位间距)`，下限保留 5 万点。纯比例尺驱动、随缩放**连续**变化，与行政区尺度无关。之所以用中位数：多年备份文件里成千上万条轨迹首尾拼接出的"瞬移"长段会把总长/均值灌水几个数量级，中位数对此免疫（此前两版启发式先后倒在"包围盒面积均摊"和"总长灌水"上）。性能面板"采样率"行实时显示 `1/stride` 与上屏点数；拾取按同一采样率跳步。想看全量密度可临时关掉"自动降采样"。

**460MB / 190 万点的大文件要等多久？**
两趟式解析器 + Debug 也开 `-O` 之后，460MB 大约 1–2 秒内（此前 24 秒的数字来自 `-Onone` Debug 构建 + 旧版逐点 append 架构的叠加）。加载后的投影/测速/着色对 190 万点合计约 100–200ms。

**为什么导入 460MB，导出只有 205MB？**
点一个不少、坐标/海拔/时间完整保留——变小的是"包装"：原文件由记录 App 生成，每个点往往还带 `<extensions>`（速度/航向/精度等厂商字段）、更深的缩进和更长的冗余小数位；本 App 只解析并保留 lat/lon/ele/time 四个字段，导出时以紧凑格式重写（每点一行、坐标 7 位小数≈厘米级精度）。语义上这是无损的位置轨迹，字节上是精简重编码。若以后需要原样保留 extensions 可以再加"原文透传"模式。

**交互为什么现在更顺滑了？**
之前覆盖层重绘由地图 delegate 回调驱动、再经异步合并，节拍和显示器刷新错位，即使 GPU 只要 0.2ms 也只有 ~23fps。现在交互期间由 displayLink 按 vsync 逐帧主动渲染（静止 0.35 秒自动暂停，零功耗），帧率贴满显示器刷新率。

**工程打不开 / 报工程文件损坏？**
备用方案手动建工程：File → New → Project… → macOS → App（SwiftUI）；删掉模板的两个 swift 文件；把 `GPXPointViewer/` 里全部 `.swift`、`.metal`、`.xcstrings`、`Assets.xcassets` 和资源文件（`Regions.bin`、`earth_texture*.png`、`land_mask.*`、`moon_texture.png`）拖进工程（Add to target）；Signing & Capabilities 确认 App Sandbox 下勾选 Outgoing Connections (Client) 与 User Selected File → **Read/Write**（导出的保存面板需要写权限，只给 Read Only 会在导出时崩溃）；⌘R。

**编译报错？**
把完整报错发给我（Claude），我来修。

**地图空白？** 需要联网加载瓦片；拖动一下地图会触发加载。

**速度数值不像火车速度？** 这些 GPX 的时间戳是 gpx.studio 合成的，相邻点距离/时间差不完全物理一致，App 显示的就是数据真实算出的值；色标按百分位缩放所以相对快慢依然可读。
